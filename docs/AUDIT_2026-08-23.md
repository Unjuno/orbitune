# Orbitune Full Repository Audit — 2026-08-23

Status: **ACTIVE AUDIT RECORD**

This audit cross-checks product/design documents, implementation, data/training paths, compatibility rules, CI, and production blockers. It distinguishes issues fixed during the audit from risks that still require experiments or implementation.

## Executive result

The repository has a coherent product direction and a viable experimental Compound data path, but it is **not yet safe to freeze a production Compound ABI or publish an official Compound Base**.

The highest-risk inconsistencies found in the audit were stale 3M architecture/roadmap documentation, semantically unsafe same-step Compound ordering, unversioned Compound JSONL rows, duplicated record-width constants, and an accidentally armable scheduled legacy training loop. Those were corrected during this audit.

The highest remaining blockers are long-time representation beyond 1536 steps, start/end sequence semantics, expressive pedal/rare MIDI preservation, explicit field cardinalities/masks, production-level deduplication, and the missing Compound Base model.

## Fixed during this audit

### A1 — stale architecture documentation — FIXED

`docs/ARCHITECTURE.md` still described the 4x240 ~3M model as the current reference ABI while `compat.py`, README and actual reference code use the 4x448 ~10.2M Theory-REMI reference. The document now distinguishes:

- historical ~3M config;
- operational legacy/reference ~10.2M Theory-REMI path;
- experimental future Compound path.

### A2 — obsolete roadmap — FIXED

`docs/ROADMAP.md` still required a 3M Base and release-asset workflow. It now reflects the Compound critical path and real-data validation gates.

### A3 — stale contribution guides — FIXED

`CONTRIBUTING_BASES.md` and `CONTRIBUTING_ADAPTERS.md` referenced the hidden-240 Base as the current Adapter ABI. They now describe the operational hidden-448 reference path and explicitly forbid publishing community Bases/Adapters against the experimental Compound ABI before freeze.

### A4 — same-step MIDI state ordering — FIXED

Compound canonicalization previously sorted same-step events by enum value, which could emit NOTE before TEMPO/TIME_SIGNATURE and PROGRAM before BANK. This is causally wrong for model conditioning and can reverse Bank Select → Program Change semantics.

Canonical order is now:

```text
TIME_SIGNATURE
TEMPO
BANK
PROGRAM
CC
PEDAL
PITCH_BEND
CHANNEL_PRESSURE
POLY_PRESSURE
NOTE
```

A regression test covers the ordering.

### A5 — Compound JSONL ABI mixing — FIXED

Training JSONL rows previously contained records without the tokenizer ABI. A future record layout could therefore be silently mixed into old training data.

Each row now carries:

```text
tokenizer_abi
record_width
```

and the loader rejects mismatches.

### A6 — duplicated record-width constant — FIXED

The width `12` was duplicated across tokenizer/dataset/training code. `COMPOUND_RECORD_WIDTH` now lives in the Compound tokenizer module and consumers import it.

### A7 — malformed Compound training records — PARTIALLY FIXED

The loader now rejects invalid event type, MIDI channel, timing-factor indices, continuous-factor indices, negative values, wrong record width and wrong ABI before tensors are built.

Event-specific `a1..a4` cardinality/mask validation still depends on the Compound model schema and remains open.

### A8 — scheduled legacy training could be armed accidentally — FIXED

The scheduled continuous workflow still trains Theory-REMI. Previously, adding two `.tokens` files automatically armed it even though Compound is now the production direction.

It now also requires the explicit marker:

```text
data/continuous/ENABLE_LEGACY_REFERENCE_TRAINING
```

Compound continuous training must get a separate gate after its model/checkpoint ABI exists.

## Remaining P0 blockers — must close before Compound ABI freeze

### P0.1 — silent clipping above 1536 timing steps

`quantize_time()` currently clips DELTA/DURATION values above 1536 steps. At 96 steps/qn this is 16 quarter notes (four 4/4 bars).

Consequences:

- a rest/gap longer than four bars is shortened silently;
- a held note longer than four bars is shortened silently;
- absolute decoded timing after a clipped DELTA drifts earlier than the source;
- current roundtrip claims do not apply to such values.

Do **not** solve this by blindly increasing a flat vocabulary. Candidate experiment:

- extend coarse boundaries geometrically (e.g. 1536, 3072, 6144, ...);
- compare extended coarse+residual against explicit long-time/skip events;
- measure real-corpus frequency, MAE/P95 and sequence cost.

Acceptance condition: no silent timing truncation in an official tokenizer.

### P0.2 — BOS/EOS / unconditional generation semantics are absent

Compound records currently represent only MIDI events. Song-local windows avoid boundary crossing, but the production model still needs defined semantics for:

- beginning of composition;
- unconditional generation with no MIDI prompt;
- end/stop prediction;
- optional continuation where no EOS should be forced.

This must be an explicit ABI decision before model output heads freeze.

### P0.3 — field cardinalities and event-specific masks are not frozen

`a1..a4` are generic storage slots. The model needs a single schema defining, for every event type:

- which fields are active;
- each field's categorical cardinality;
- which factorized heads apply;
- training-loss masks;
- inference validity masks;
- intra-event conditioning order.

Do not infer these independently in model/training/export code.

### P0.4 — Compound Base model is not implemented

The data path reaches `[B,S,12]` tensors, but the actual production-candidate model is still missing.

Next implementation:

```text
factorized field embeddings
→ causal Transformer
→ event type
→ event-conditioned lightweight autoregressive attribute cascade
→ masked factorized losses
```

Synthetic overfit and tiny-real-MIDI overfit must pass before corpus-scale experiments.

### P0.5 — production corpus deduplication is not composition-aware yet

Current Compound split prevents exact-byte SHA-256 duplicates from crossing train/validation. This is useful but insufficient.

Equivalent or near-equivalent arrangements/transpositions/exports can still leak. Production corpus work needs composition/near-duplicate grouping before held-out evaluation claims are trustworthy.

## Remaining P1 semantic/data issues

### P1.1 — PEDAL currently loses half-pedal information

CC64 is converted to `PEDAL` with only 0/1 state (`value >= 64`). MIDI supports the full 0..127 controller value and real piano data may contain half-pedal behavior.

Experiment required:

- measure CC64 value distribution in the target corpus;
- compare binary pedal against factorized continuous pedal;
- accept binary only if the lost range is empirically irrelevant to the target model.

### P1.2 — BANK representation canonicalizes raw CC0/CC32 messages

The parser emits a combined `(MSB, LSB)` BANK state on either CC0 or CC32. This is useful as musical state but is not byte-level reversible: it does not preserve which selector was emitted by the source at that instant.

Decide explicitly whether Orbitune models canonical instrument state or exact MIDI controller traffic. Current design should be documented as canonical-state modeling if retained.

### P1.3 — tempo precision is canonicalized to integer BPM

Tempo meta events are converted from integer microseconds-per-quarter to rounded integer BPM. This is compact but not exact.

Measure real tempo distributions and reconstruction error before freezing the field. A factorized tempo representation may retain enough precision cheaply.

### P1.4 — TIME_SIGNATURE drops auxiliary meta bytes

The parser retains numerator/denominator but drops MIDI time-signature metronome and 32nd-note fields. This is probably acceptable for generative music structure, but it means the Compound schema is intentionally semantic rather than lossless SMF roundtrip.

### P1.5 — dangling notes are silently dropped

If a track ends with unmatched NOTE-ON events, the parser does not currently emit them or reject the file. Production ingestion should either reject/report malformed dangling notes or apply an explicit deterministic repair policy.

### P1.6 — SysEx/SMPTE/type-2 and some meta semantics are outside scope

Current Compound parser ignores SysEx payloads and unrelated meta events, rejects SMPTE division and MIDI format 2, and does not model text/key-signature/port metadata. The public claim should therefore be “production musical MIDI event scope,” not lossless support for every possible SMF payload.

### P1.7 — track/port semantics need a corpus check

Format-1 tracks are merged into one global event stream. Standard channel semantics often make this correct, but MIDI Port meta events and unusual files can distinguish destinations not represented by the current schema. Measure prevalence before declaring this irrelevant.

## Remaining P1 compatibility/runtime issues

### P1.8 — Base manifest is not yet rich enough for arbitrary future architectures

The Base manifest records architecture/tokenizer strings and artifact hashes, but it does not carry a frozen structured architecture config or runtime ABI/config hash. The current browser/runtime is shape-specific.

Before accepting Compound community Bases, define a manifest contract that prevents “same string, incompatible shape/field layout” ambiguity.

### P1.9 — Compound Web/export path does not exist yet

Current ONNX/Web ABI is Theory-REMI-specific. Do not reuse it implicitly for Compound.

### P1.10 — Compound continuous-training path does not exist yet

The current scheduled workflow is explicitly legacy-only after this audit. Compound needs separate resumable checkpoint/optimizer/RNG state and health/snapshot integration after its model exists.

## P2 hardening / maintainability

### P2.1 — GitHub Actions are version-tag pinned, not commit-SHA pinned

Workflows use actions such as `actions/checkout@v4` and `actions/setup-python@v5`. This is common, but higher supply-chain assurance would pin third-party actions to immutable commit SHAs and use dependency update tooling.

### P2.2 — architecture constants remain split between legacy `compat.py` and future Compound schema

This is intentional during migration, but future code should avoid generic names like `ARCHITECTURE_ABI` meaning only Theory-REMI once Compound is operational. Prefer explicit legacy/reference versus Compound identifiers.

### P2.3 — `scripts/prepare_compound_corpus.py` is not yet integrated into the main CLI

Acceptable during experiment phase. Integrate only after the Compound input ABI stabilizes so the public CLI does not imply production support prematurely.

## CI/test audit

`test.yml` runs the whole Python `tests/` suite on pushes and pull requests, so Compound tests are included automatically.

However:

- the audit could not independently confirm the latest GitHub Actions run result through the available connector;
- full local repository checkout was not available in the execution container during this session;
- therefore “tests exist in CI” is confirmed, while “the latest full suite passed after every audit commit” must be checked in GitHub Actions.

The next session should inspect the `test` workflow before continuing model implementation.
